# QuikBankAccountBalancer

Анализ инвестиционного портфеля QUIK с возможностью настройки целевых распределений активов.

## Описание

Этот проект с открытым исполняемым кодом позволяет анализировать инвестиционный портфель, созданный в QUIK (система для торговли на фондовых и срочных рынках), и сравнивать его с заданными целевыми распределениями активов. Программа предоставляет интерактивный интерфейс для просмотра текущего состояния портфеля и редактирования целевых показателей.

## Особенности

- Анализ фондового и срочного рынка
- Визуализация распределения активов
- Настройка целевых распределений активов
- Интерактивный интерфейс с помощью Streamlit
- Поддержка различных классов активов (Акции, Облигации, ETF, Фьючерсы, Золото и др.)

## Зависимости

- Python 3.12
- Streamlit
- pandas
- plotly
- numpy


## Настройка и интеграция QuikPy

Библиотека QuikPy используется для подключения к QUIK (без нее не будет формироваться отчет по кнопке "Из QUIK"). 
Чтобы все работало необходимо скачать или склонировать проект с GitHub: https://github.com/cia76/QuikPy
И затем скопировать папку "QuikPy" в папку с моей программой.
Далее следовать инструкциям по интеграции в самом QUIK - см. https://github.com/cia76/QuikPy/blob/master/README.md#%D0%BD%D0%B0%D1%87%D0%B0%D0%BB%D0%BE-%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D1%8B
Там написано следующее:
1. Скопировать папку со скриптами LUA **QUIK\lua** в папку установки QUIK
2. Скопировать папку **QUIK\socket** в папку установки QUIK
3. Библиотека core.dll для LUA версии 5.4.1 также доступна в проекте QUIK# 
4. Запустите QUIK и в меню **Сервисы** выберите **LUA скрипты**, добавьте и запустите скрипт **QuikSharp.lua**
Если в окне сообщений QUIK выдаст **QUIK# is waiting for client connection...**, то скрипт запущен успешно.

## Запуск

используйте `run_app.bat` для автоматической установки и запуска.

## Использование

После запуска приложения в левой панели можно выбрать один из способов загрузки данных портфеля:

1. **"Из QUIK"** - загружает данные непосредственно из QUIK (требует подключения к системе)
2. **"Последние данные из QUIК"** - загружает последние данные из файла `direct_portfolio.txt`, создаваемого при загрузке через "Из QUIК"
3. **"Тестовые данные"** - загружает демонстрационные данные из файла `test_portfolio.txt`

Данные будут отображены в виде графиков и таблиц, а также отображены отклонения от целевых распределений.

- **Анализ** - отображение текущего состояния портфеля
- **Редактор целей** - настройка целевых распределений активов

📋 Рекомендуемые сделки
Если `Целевые_контракты ≠ Кол_контрактов_отчета`, показывается таблица с рекомендацией:
- **Покупка** — если целевых контрактов больше текущих
- **Продажа** — если целевых контрактов меньше текущих
- **Нет целей - продать** - если уже в портфеле были активы - они лишние

## Настройка целевых распределений (создается сам через "редактор целей")

Целевые распределения задаются в файле `targets.json`:

```json
{
  "classes": {
    "ОФЗ": 20.0,
    "Корп. облигации": 10.0,
    "Акции РФ": 5.0,
    "ETF": 5.0,
    "Золото": 10.0,
    "Фьючерсы": 15.0,
    "Ликвидность": 35.0
  },
  "tickers": {},
  "futures_overlay_classes": [
    "ОФЗ",
    "Корп. облигации",
    "ETF"
  ],
  "futures_buffer_pct": 15.0
}
```

## ⚠️ Важное замечание про расчет фьючерсов

**Текущая реализация расчета для фьючерсов корректно работает только для ОДНОГО тикера фьючерса в портфеле.**

Если в портфеле несколько фьючерсных тикеров:
- Расчет целевого количества контрактов распределяется пропорционально текущим позициям
- Это может давать некорректные результаты, так как разные фьючерсы имеют разные ГО и номинал на контракт
- Для нескольких тикеров рекомендуется вручную задавать целевое распределение в редакторе целей

## Арифметика диаграмм фьючерсов

В разделе «Фьючерсы — структура обеспечения» отображаются две кольцевые диаграммы: **Текущая** и **Целевая** структура обеспечения.

### Данные из отчета QUIK (на один тикер):
- `Номинал_отчета` — общий номинал базового актива (сумма по всем контрактам)
- `ГО_отчета` — общая сумма обеспечения (ГО) по всем контрактам
- `Кол_контрактов_отчета` — количество контрактов в портфеле
- `Номинал_1_контракта = Номинал_отчета / Кол_контрактов_отчета`
- `ГО_1_контракта = ГО_отчета / Кол_контрактов_отчета`

### Параметр настроек:
- `buffer_pct` — процент буфера от номинала (настраивается в «Редакторе целей», по умолчанию 15%)

---

### 📊 ТЕКУЩАЯ структура обеспечения
Все значения берутся **из отчета QUIK** (фактическое состояние портфеля):

| Сектор | Формула |
|--------|---------|
| **Номинал** | `Номинал_отчета` |
| **ГО** | `ГО_отчета` (сумма ГО по всем контрактам) = `Кол_контрактов_отчета × ГО_1_контракта` |
| **Буфер текущий** | `Номинал_отчета × buffer_pct / 100` |
| **Распределённая ликвидность** | `Номинал_отчета − ГО_отчета − Буфер_текущий` |

> **Сумма секторов = Номинал_отчета**
>
> В легенде диаграммы показывается: `ГО (N конт. × ГО_1_контракта)`

---

### 🎯 ЦЕЛЕВАЯ структура обеспечения
Номинал берется из **целевого распределения** (класс «Фьючерсы»), остальное рассчитывается:

| Сектор | Формула |
|--------|---------|
| **Номинал** | `Целевой_номинал_фьючерсов` (значение класса «Фьючерсы» из целевого распределения) |
| **Целевые контракты** | `floor(Целевой_номинал_фьючерсов / Номинал_1_контракта)` — **округляется ВНИЗЬ до целого** |
| **ГО** | `Целевые_контракты × ГО_1_контракта` |
| **Буфер целевой** | `Целевой_номинал_фьючерсов × buffer_pct / 100` |
| **Распределённая ликвидность** | `Целевой_номинал_фьючерсов − ГО − Буфер_целевой` |

> **Сумма секторов = Целевой_номинал_фьючерсов**
>
> В легенде диаграммы показывается: `ГО (N конт. × ГО_1_контракта)`
